# Profile — the one file that is about a specific person

**Forking this repo? Copy this to `profile.md` and fill it in.** Everything else in the repo is
method, evidence, or tooling and applies to anyone. This file is the input everything else reads.

`profile.md` is gitignored on purpose. The author's real one stays on the author's machine; yours
should stay on yours unless you decide otherwise. Nothing in the repo breaks if it's absent —
`scans/scans.md` carries the worked example that the method is actually taught on.

Work through `INTAKE.md` first. It tells you which of your answers rewrite which sections, ordered
by how much they rewrite — not by how comfortable they are to answer.

---

## Who

- Sex, age, height, current weight.
- Training status in one honest sentence. Not "getting back into it" — what does the log say?
- Any condition a doctor actually flagged. **Absence of a diagnosis is an assumption, not a
  clearance**, and it gates the protein ceiling (`INTAKE.md`, tier 2). Write down which it is.

## Baseline — <date>

Audit the derivation chain before trusting any number here — `scans/scans.md` is the worked
example, and `PLAYBOOK.md` rules 1–2 are the procedure.

- Weight, and how it was measured.
- Any body-composition reading, **with the method named** and its uncertainty stated. Never a bare
  percentage. If your device's bias direction isn't established in the literature, say so and give
  a range (`abs.md` is this repo's worked example of retracting a correction that didn't hold up).
- Prior trend, if you have two measurements: rate of change, and what it implies about intake.

## Training status

The question that matters is not "how long was the gap" but "what does hard data say happened
across it." Self-report loses to measurement — `PLAYBOOK.md` rule 9. A scan showing muscle
retained across a supposed layoff changes the ramp from a beginner reintroduction to about a week.
Memory alone doesn't.

## Derived targets

Outputs, not inputs. Recompute them from your own numbers; copying anyone else's defeats the point.

| Target | Value | Where it comes from |
|---|---|---|
| BMR seed | | Katch-McArdle if you have lean mass, Mifflin if you only have bodyweight |
| Calories | | A seed to be corrected by trend, never a prescription — see the calibration rule |
| Protein | | 1.6–2.2 g/kg; Morton 2018's breakpoint is ~1.6, above which more stops buying anything |
| Fat | | A floor, not a target |
| Weekly sets | | `program.md`, ~10–14 per muscle |

**No formula knows your TDEE to better than about ±300 kcal.** Itemize every term before accepting
a sum — the common handwritten version undercounts NEAT and TEF while overcounting workout burn,
which is how "maintenance" gets mislabelled as a bulk.

**The calibration rule replaces the formula.** Fix all three of these *before* you start, so
you're not deciding in the moment you're most motivated to rationalize: the metric (daily morning
weigh-in, weekly average), the trigger (gaining more than X/week), and the adjustment (±150 kcal).

## Measurement protocol

- Whatever device you use: fixed conditions, fixed interval, trends only. **Never compare across
  measurement methods** — the disagreement between two methods is larger than the change you're
  looking for.
- Track a directly measured proxy (skinfold mm at a fixed site, fixed-condition photos) rather than
  a device-derived body-fat percentage (`abs.md`).
